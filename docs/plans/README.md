# Planes de issues

Los cambios no triviales iniciados desde un issue usan
`issue-to-change` y guardan su plan como:

```text
docs/plans/issue-<id>-<slug>.md
```

Cada plan debe contener problema, alcance, criterios verificables, mapa de
impacto, seguridad, implementación, pruebas, documentación, grafo, riesgos y
evidencia final. No guardar secretos, tokens ni datos personales reales.
